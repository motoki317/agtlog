# Context

agtlog needs a terse, keyboard-first terminal browser: one interleaved session list, a drill-in
timeline, fuzzy filtering, live updates, help, and safe behavior at 80 columns. The interaction
target is k9s and lazygit, where a user can move, filter, and open a resource without menus.

The distinguishing row is one top-level session with tokens and cost rolled up recursively through
its subagents. The stack must keep the selection on that row while updates reorder the list, and
it must make state transitions testable without a real terminal.

# Decision

We use Bubble Tea for the event loop, Bubbles for the viewport, text input, and key bindings, and
Lip Gloss for sparse semantic styling. The application has a session list and detail screens that
stack as the reader drills in. Help temporarily replaces the current screen instead of adding a
general modal system.

`Update` transforms model state and returns commands for discovery and lazy detail loading. `View`
renders that state. Blocking I/O stays outside both methods. Tests call `Update` and `View` directly
for filters, sort order, navigation, live upserts, expansion, and width safety. teatest golden
frames cover representative list and detail screens.

The list follows a k9s-style column budget and drops lower-priority columns when the terminal is
narrow. agtlog sanitizes text, then measures and truncates it by terminal display width, and only
then applies a style. Headers and key bars fit the terminal width.

Color communicates agent identity and warnings but never carries meaning alone. A non-empty
`NO_COLOR` removes the palette and keeps glyphs and layout. Non-terminal output becomes one complete
plain static frame. Interactive runs use the alternate screen, and Bubble Tea restores the original
screen on a normal quit or a context cancellation. The CLI runner owns that boundary, so tests and
redirected output never enter the alternate screen, and pipelines receive no terminal-control bytes.

# Impact

A new binding must be one keystroke, never a sequence, and the help view of each screen where it
acts must list it. A new column must define its width, its truncation, and its priority on a narrow
terminal. Untrusted log text must pass through `model.TerminalText` or `model.TerminalLine` before
any Lip Gloss or ANSI width calculation.

# Alternatives

We rejected **tview** because its widget and callback model makes state transitions harder to test
as values.

We rejected **raw termbox-style rendering** because agtlog would own input decoding, resize
behavior, display-width truncation, scroll state, and terminal restoration. Those mechanics do not
distinguish the product.

We rejected **the Bubbles table** for session and subagent rows because it is not aware of ANSI
styling when it allocates width. It truncates each cell by rune width and counts escape sequences as
columns, so a cell that carries its own color loses visible text.
