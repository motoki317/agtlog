# Context

agtlog needs a terse, keyboard-first terminal browser: one interleaved session list, a drill-in
timeline, fuzzy filtering, live updates, help, and safe behavior at 80 columns. The interaction
target is k9s and lazygit, where a user can move, filter, and open a resource without navigating
menus.

The distinguishing row is one top-level session with tokens and cost rolled up recursively through
its subagents. The stack must keep that row stable while updates arrive and make state transitions
testable without a real terminal.

# Decision

agtlog uses Bubble Tea for the event loop, Bubbles for table, viewport, text input, help, and key
bindings, and Lip Gloss for sparse semantic styling. The application has two screens: a session
list and a detail timeline. Help temporarily replaces the current screen rather than adding a
general modal system.

`Update` transforms model state and returns commands for discovery or lazy detail loading. `View`
renders that state. Tests call both methods directly for filters, sort order, navigation, live
upserts, expansion, and width safety. teatest golden frames cover representative list and detail
screens.

The list follows a k9s-style fixed column budget and drops rightmost columns when the terminal is
narrower. Text is sanitized and truncated by terminal display width, and both headers and footers
remain within 80 columns. Detail events default to collapsed summaries; one keystroke expands a
turn or nested subagent.

Color communicates agent identity and warnings but never carries meaning alone. `NO_COLOR`
removes the palette while retaining glyphs and layout. Non-terminal output becomes a complete plain
static frame. Interactive runs use the alternate screen, and Bubble Tea restores the original
screen on normal quit or context cancellation.

# Consequences

- Navigation and rendering can be tested as deterministic state transitions.
- Bubbles supplies familiar terminal behavior for resize, scrolling, input focus, and help.
- The fixed-width table makes truncation policy explicit and keeps the recursive rollup legible at
  the 80-column minimum.
- A terminal that lacks color still exposes estimates, missing prices, errors, selection, and tree
  structure through text and glyphs.
- The UI inherits Bubble Tea's event and command model, so blocking I/O must remain outside
  `Update` and `View`.

# Impact

New screens or bindings must fit the existing single-key budget and help view. New columns must
define a width, truncation behavior, and narrow-terminal priority. Rendering untrusted log text must
continue through the terminal sanitizer before Lip Gloss or ANSI width calculations.

The alternate-screen boundary belongs to the CLI runner. Tests and redirected output do not enter
it, which keeps automation readable and avoids terminal-control bytes in pipelines.

# Alternatives

**tview** was rejected because its widget and callback model would make the application's state
transitions harder to exercise as values, while Bubble Tea already provides the table, viewport,
input, and command composition needed here.

**Raw termbox-style rendering** was rejected because agtlog would have to own input decoding,
resize behavior, display-width truncation, scroll state, and terminal restoration. Those mechanics
do not distinguish the product.

**A web UI** was rejected because it would add a server, browser lifecycle, and a second security
surface to a local read-only terminal tool. It would also abandon the keyboard grammar that defines
the product.

# Notes

The complete visual and interaction vocabulary is recorded in `docs/design.md`. This ADR fixes the
stack and testing model; it does not freeze every color or column width.
